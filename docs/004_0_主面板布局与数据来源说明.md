# 基金主面板（Dashboard）布局与数据来源 - 完整说明文档

> 最后更新：2026-07-31
> 目的：让后续 AI 快速理解主面板「每一列的数据从哪来、由谁计算、休市时该显示什么」，并规避 2026-07-30 发现的实时估值重大 bug。

---

## 一、主面板是什么

主面板 = 网站首页（Dashboard.vue）顶部那张**按分类 Tab 切换的基金汇总表**，是用户打开网站第一眼看到的界面。它与另外两个界面口径不同，务必区分：

| 界面 | 入口 | 估值列含义 | 数据来源 |
|------|------|-----------|---------|
| **主面板** | `/` (Dashboard.vue) | `rt_val`=实时估值（每次请求**后端现算**）；`static_val`=静态估值（每日流水线算好存 DB） | `get_unified_dashboard_data()` |
| **历史记录弹窗** | 点名称/静态估值列 | 仅展示 `unified_fund_history` 历史，无 rt_val | `get_fund_history()` —— 详见 `004-1_历史记录静态估值说明.md` |
| **实时沙盘页** | 点实时估值列 → `/analysis?code=xxx` | `rt_val` 由**前端** `useValuationCalculator` 独立现算 | 前端计算，无活价即空 |

**关键认知**：主面板的 `rt_val` 与沙盘页是**同一语义**（都用实时价现算），但主面板经后端、沙盘页经前端。2026-07-30 修复前两者不一致（主面板在休市时显示陈旧值、沙盘页正确显示空），现已对齐。

## 二、布局：分类 Tab 与列

### 2.1 分类 Tab（currentTab）
默认可选：`QDII亚洲` / `国内LOF` / `白银` / `QDII欧美` / `QDII日本` / `黄金原油` / `现金管理`。

**净值列 T-1/T-2 标签随 Tab 变化**（见 Dashboard.vue 673-677）：
- `QDII亚洲` / `国内LOF` / `白银` → 列名 **「T-1日净值」**
- `QDII欧美` / `QDII日本` / `黄金原油` → 列名 **「T-2日净值」**（跨境 QDII 净值延迟公布）
- 其它 → 「T-2/1日净值」

### 2.2 默认列顺序（allColumns，Dashboard.vue 291-470）
```
★(收藏) | 代码 | 名称 | 现价 | 涨跌幅 | 实时估值(rt_val) | 实时溢价 | T-1/T-2日净值 | 净值日期
       | 静态估值(static_val) | 静态溢价 | 成交额(万) | 份额(万) | 新增(万) | 换手率
       | 指数价 | 指数涨跌 | 指数名称 | 申购 | 赎回
```
各 Tab 的动态增删/改名：
- **白银 Tab**：额外插入 `实时成交价(AG0)`、`昨结算价(AG0)`、`实时估值(SI)`、`实时溢价(SI)`；并把「实时估值/静态估值」改名为「参考估值/官方估值」、「实时溢价/静态溢价」改名为「参考溢价/官方溢价」。
- **QDII欧美/黄金原油/白银**：隐藏 `指数价/指数涨跌/指数名称` 列（跨境基金无单一跟踪指数）。
- **现金管理 Tab**：隐藏份额/新增/换手率/指数/申赎，插入「折价几根毛」「溢价」等债券 ETF 专属列。

### 2.3 点击行为（重要）
- 点 **实时估值(rt_val)** 单元格 → 跳转沙盘页 `/analysis`（实盘计算）。
- 点 **静态估值(static_val)** 或 **名称** → 弹出**历史记录弹窗**（见 004-1）。
- 两个「估值」列含义不同，切勿混为一谈。

## 三、每一列的数据来源（重点）

主面板数据全部来自 `ArbDashboard/backend/services/fund_service.py :: get_unified_dashboard_data()`。

| 列 | 字段 | 来源 | 计算/取数位置 | 休市时应为 |
|----|------|------|--------------|-----------|
| 现价 | `price` | 实时行情优先级链 `tdx→guojin→galaxy→tencent→sina`（YAML 单一真相源） | 1240-1260 取 realtime quote | A股休市则无（场内价本就停） |
| 涨跌幅 | `price_change` | `(price - prev_close)/prev_close`，prev_close 取腾讯日K 不复权 close | 1239-1243 | 同上 |
| **实时估值** | `rt_val` | **盘中后端现算**（见第四节，按 category 走不同算法）；**盘后自动回退**：优先当日 15:00 冻结值，否则盘中最后有效缓存值（见 4.2） | 1280-1444 各分支 + `apply_freeze_to_dashboard` | 盘中无活价→`None`（前端 `-`）；盘后回退显示冻结/缓存值并带蓝色「冻」徽章 ⚠️ |
| 实时溢价 | `rt_premium` | `price/rt_val - 1`（需 rt_val & price 均>0） | 同 rt_val 分支内 | `None` |
| 净值 | `nav` | `unified_fund_history.nav`（T-1 或 T-2，依 Tab） | 1195-1198 | 仍是最近一个交易日净值 |
| 净值日期 | `nav_date` | `unified_fund_history.date` | 1198 | 同上 |
| **静态估值** | `static_val` | **不是现算**，读 `unified_fund_history.static_val`（每日流水线 step10 算好） | 1200-1208 | 仍是最近一个交易日值 |
| 静态溢价 | `static_premium` | DB 字段 | 同 static_val | 同上 |
| 成交额(万) | `volume` | 实时 `rt['amount']`（万元） | 1256/1269 | 休市为 0 |
| 份额(万) | `shares` | `unified_fund_history.shares` | 1220-1224 | 最近值 |
| 新增(万) | `shares_added` | `shares(T) - shares(T-1)` | 1224 | 最近值 |
| 换手率 | `turnover_rate` | **`trade_volume(手) / shares(万)`** | 1230-1232 / 1262 | 最近值 |
| 指数价/涨跌/名称 | `index_close/index_pct/index_name` | `index_changes_map`（跟踪指数实时涨跌幅） | 1447-1466 | 无实时则无 |

### ⚠️ 换手率计算铁律（极易错）
- **换手率(%) = 成交量(手) ÷ 份额(万)**，不是成交额。
- 数据库 `volume` 列是**成交额(万元)**（= 实时 `rt['amount']`），**不是**成交量！
- 成交量存在 `trade_volume`（手）：`trade_volume = rt['volume'] / 100`（股→手，腾讯日K `it[5]` 抓取回填）。
- 新增换手 = `trade_volume / shares_added`（仅当 `shares_added > 0` 显示）。

### ⚠️ 符号命名铁律（与 004-1 一致）
- 区域锚点 symbol **必须带 `^`**：`^GLD-EU`、`^USO-HK`、`^GLD-JP`。
- 核心锚点无前缀：`GLD`/`USO`/`XOP`/`SLV`/`SPY`/`QQQ`/`INDA`。
- 取价时 `^GLD-EU` 折叠成 `GLD` 去重取价；权重列名必须带 `^`。

## 四、实时估值（rt_val）的计算分支（本次 bug 核心）

`rt_val` 按 `category` 走不同算法，全部要求「有实时价」才能算，**无活价必须返回 `None`**：

| category | 算法分支 | 实时价来源 | 守卫 |
|----------|---------|-----------|------|
| 黄金原油 / QDII欧美（有 basket/trade_etf） | `DynamicValuationCalculator` 矩阵/魔法公式 | `market_data_service.get_realtime_quote(GLD/USO/XOP/SPY/QQQ...)`（IB/Futu/客户端源） | **去重基准守卫**：任一去重基准缺活价 → `rt_val=None` |
| QDII日本 | NK 期货 + 在岸价 | `get_realtime_quote('NK')`（hf_NK）；新浪能否爬到 NK 延时 | 无 NK 活价 → `None` |
| 白银（161226） | AG0 期货比值 | 东财SSE长连接 → localhost:5000 → 新浪 `nf_AG0` | **`is_shfe_open()` 交易时段守卫**：休市 → `None` |
| 国内LOF / QDII亚洲（无 basket，有 related_index） | 指数涨跌幅法 | `index_changes_map`（跟踪指数实时 pct） | 无指数实时 → `None` |
| 债券ETF（现金管理） | 债券估值法 | 国债指数/期货 | 无活价 → `None` |

### 4.1 本次发现的重大 bug（2026-07-30）

**现象**：北京时间 16:49（美股夜盘已结束、IB 未运行）主面板仍显示 160719 的 `rt_val=1.8041` 等数值。东哥指出：此刻根本没有美股 ETF 实时价，这些值**是错的、误导用户**；而点进沙盘页实时估值却是空的（正确）。

**根因**（三处）：
1. `arbcore/calculators/valuation_data_engine.py :: assemble_dynamic_components`：实时价缺失时退化用 **T-1 基准价（昨收）** 当实时价。
2. `fund_service.py` 161226 专属 AG0 块：休市时新浪 `nf_AG0` 仍返回**上一交易时段收盘价**，被直接当「实时」。
3. `fund_intraday_quotes` 采样表曾有 **6533 行陈旧快照**（2026-06 的）兜底喂给实时估值。

**修复**（均已落地，仍未 commit）：
- 篮子基金：新增「去重基准数」守卫（区域后缀折叠到基础代码取价，`current_etfs` key 数恒等于去重基准数，故按去重集合而非 portfolio 长度判定；任一缺活价 → `_basket_missing_etf=True` → `rt_val=None`）。
- 161226：新增 `is_shfe_open()` 交易时段守卫（`arbcore/utils/market_calendar.py`），休市 → 丢弃 AG0 价 → `rt_val/si_val=None`。
- 采样表：加「仅当日」守卫（非当日采样→置 None）。
- 删除 `fund_intraday_quotes` 全部 6533 行陈旧记录（VACUUM 回收）。

**验证**：
- `arbcore/scripts/verify_realtime_guard.py`：模拟 IB/富途全关，美股ETF篮子基金 + QDII日本四只 全部 `rt_val=None` ✓。
- `arbcore/scripts/verify_161226_ag0_guard.py`：monkeypatch `is_shfe_open=True` + 受控 AG0 价 → 161226 `rt_val=1.6013`，证明守卫**不误杀**开盘时段 ✓。

### 4.2 收盘后冻结与最后有效估值机制（#47, 2026-07-31）

**问题背景**：第四节的现算守卫保证「无活价 → rt_val=None」，但 A股 15:00 收盘后 LOF 价格已冻结，海外标的（NK 期货 / 美股夜盘）继续波动对实时估值已无套利意义（LOF 不能交易）。若直接显示 `-`，用户盘后看不到任何估值锚点。

**方案**：把 15:00 那一刻算好的 rt_val 冻结下来，盘后/重启显示冻结值；并额外缓存盘中最后有效估值，解决「用户不常驻、15:00 没拍到 → 全空白」。

**设计铁律（东哥拍板）**：
- 统一对所有基金（国内LOF / QDII香港 / QDII日本 / QDII欧美）拍快照，**不分市场**；绝不搞「按市场分别冻结」（港股16:00 / 美股盘前等）的复杂方案。
- 这是**主程序功能**，快照文件落在 `database/`（非 deploy）。

**回退优先级**（`apply_freeze_to_dashboard`，在 `get_unified_dashboard_data()` 末尾调用）：

| 时段 / 状态 | 显示 | 标记 | 标签 |
|-------------|------|------|------|
| 盘中（<15:00） | 实时 live（有行情） | 无 | — |
| 盘后 + 当日有 15:00 冻结 | 15:00 冻结值 | `rt_frozen=True` | 「15:00冻结」 |
| 盘后 + 无 15:00 冻结（rt_val 仍 None） | 盘中最后有效缓存值 | `rt_frozen=True` | 「最后有效 HH:MM」 |
| 盘后 + 无任何可用值 | None | 无 | 前端显示 `-` |

**两个持久化文件（都在 `database/`）**：
1. `rt_freeze.json` —— 每日 15:00:05 由 `main.py` 的 APScheduler（`CronTrigger(mon-fri 15:00:05)`）调 `snapshot_realtime_freeze()` 拍的「官方收盘锚点」。结构：`{date, frozen_at, funds:{code:{rt_val,rt_premium,price}}}`。**只冻有效 rt_val**（None 跳过），避免把空值冻成 `-`。
2. `rt_cache.json` —— 盘中每次 `get_unified_dashboard_data()` 算完，**先调 `update_rt_cache()` 合并写入**「最后有效值」。结构：`{updated_at, funds:{code:{rt_val,rt_premium,price}}}`。**合并式更新**（本次缺失不覆盖之前有效），抗网络抖动丢缓存。

**触发与兜底（main.py lifespan）**：
- 正常：APScheduler 每交易日 15:00:05 自动快照。
- 兜底：后端在盘中才启动、且已过 15:00、且今日无冻结 → 启动即补拍一次（best-effort，拍的是「启动那一刻」值，非严格 15:00:05）。常驻到 15:00 不会触发兜底。

**前端展示（Dashboard.vue + fundStore.ts）**：
- `FundItem` 新增 `rt_frozen?: boolean` 与 `rt_frozen_note?: string`。
- 实时估值列 + 实时溢价列：当 `rt_frozen` 时渲染蓝色「冻」徽章，`title` 显示 `rt_frozen_note`（「15:00冻结」或「最后有效 HH:MM」）。点击仍跳转沙盘页。

**验收口径（用户侧）**：
- 交易时段开后端（看一眼主看板）→ `rt_cache.json` 自动建立；之后盘后/重启都显示「最后有效 HH:MM」。
- 若届时后端常驻到 15:00 → 显示「15:00冻结」（优先于缓存）。

**与 4.1 的关系**：4.1 修的是「现算层被陈旧价污染 → 本该 None 却显示错值」；4.2 是「现算层正确返回 None 后，展示层再叠加一层合规回退」。二者不冲突：有「冻」徽章的回退值是预期、可信；**无徽章却显示数值**才是 4.1 的 bug 复发信号。

## 五、常见 AI 易犯错误清单

1. **把主面板 rt_val 当成「一定有值」**：盘中休市 / IB 未连 / 富途未开 时**现算层** rt_val 应为 `None`；但 A股 15:00 后由「冻结/缓存机制（4.2）」回退显示上一次有效估值并带蓝色「冻」徽章——这是**预期行为，不是 bug**。**警惕信号相反**：若盘后某基金显示数值却**没有「冻」徽章**，多半是 4.1 的陈旧价 bug 复发（现算层被污染）。
2. **混淆 rt_val（实时）与 static_val（静态/T-1）**：static_val 是每日流水线算好存 DB 的，主面板直接读；rt_val 是每次请求后端现算的。两者数值接近但语义完全不同。
3. **净值日期 T-1/T-2 随 Tab 变化**：跨境 QDII 是 T-2，别写死 T-1。
4. **换手率用成交额算**：必须用 `trade_volume(手)/shares(万)`；`volume` 列是成交额(万元)，不是成交量。
5. **区域锚点 symbol 漏 `^`**：`^GLD-EU` 不能写成 `GLD-EU`；取价时折叠后缀、权重列名带 `^`。
6. **两个「估值」列点进去的行为不同**：实时估值→沙盘页（前端现算），静态估值→历史记录弹窗（DB 历史）。
7. **修实时估值后忘了跟沙盘页对齐**：主面板与沙盘页 rt_val 必须一致（无活价都空）。回归时同时跑 `verify_realtime_guard.py`。
8. **误以为 513000/159866/513520/513880 是「国内/在岸」**：它们是 **QDII日本**，实时估值取决于 NK 期货是否在交易，无 NK 活价即空——这本来就是对的，不是 bug。

## 六、与沙盘页 / 历史记录页的口径差异（速查）

| 维度 | 主面板 rt_val | 沙盘页 rt_val | 历史记录页 |
