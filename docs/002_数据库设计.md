## 数据库概述

LOF 基金套利监控系统采用 **"大统一超级宽表"** 和 **"模块化职责分离"** 的数据库设计哲学。系统默认使用 SQLite 数据库，并强制开启 WAL (Write-Ahead Logging) 模式，以支持多线程高频写入与查询。

**数据库路径**：`d:\Study\arbTest\database\arb_master.db`（唯一生产库，约 15MB）

**覆盖项目**：ArbDashboard（JSL、LOFarb 已废弃）

**已废弃**：`jsl/jsl_monitor.db`（2026-06-09 删除）、根目录空 `arb_master.db`（0 字节，2026-07-25 删除，误连会读到空数据）

## 模块化管理器 (DatabaseManager)

数据库接口通过 `组合模式` 拆分为三个专业子管理器，另设交易/规则相关表由 `DatabaseManager` 直管 + 私有模块（`rule_engine` / `ledger_service`）读写：

### 1. 基金管理器 (`db.funds`)
- **职能**：管理 A 股基金的价格、净值、估值因子、篮子权重、申赎状态、自选与盘中快照。
- **核心表**：`unified_fund_list`, `unified_fund_history`, `fund_daily_factors`, `fund_basket_weights`, `fund_purchase_status`, `fund_watchlist`, `fund_intraday_quotes`, `fund_fees`

### 2. 市场管理器 (`db.market`)
- **职能**：管理宏观汇率、海外 ETF 收盘价、指数 K 线/实时报价、期货结算价、ETF 轮动数据。
- **核心表**：`exchange_rate`, `usa_etf_daily_prices`, `futures_daily`, `index_history`, `index_realtime_quotes`, `etf_rotation_list`, `etf_raw_api_data`

### 3. 系统管理器 (`db.system`)
- **职能**：维护 API 访问状态、数据源配置、原始数据备份（Data Lake）及全局设置。
- **核心表**：`access_sync_status`, `data_source_config`, `raw_api_data`, `app_settings`, `arbitrage_pairs`, `cdb_yield_bp`

### 4. 交易与规则表（由 DatabaseManager / rule_engine / ledger_service 管理）
- **职能**：自动化交易规则、成交台账、赎回费率配置。
- **核心表**：`auto_trade_rules`, `user_trades`, `broker_redemption_fees`

## 性能优化与设计哲学

1. **动静结合 (Upsert Strategy)**：
   - 盘中使用 `INSERT OR REPLACE` 实时覆写当天行，保持数据新鲜。
   - 盘后通过 `UPDATE` 精修官方字段（如 `nav`），实现无缝过渡。

2. **快慢分离**：
   - 指数行情分为"实时快照表"（`index_realtime_quotes`，单行缓存）与"历史 K 线表"（`index_history`，分段归档）。

3. **安全隔离**：
   - ETF 轮动模块使用物理隔离的 `etf_raw_api_data` 表，确保策略私密性。

4. **全自动清理**：
   - `db.cleanup_old_data(days=30)` 自动回收陈旧的常规行情数据，防止数据库膨胀（注意：清理逻辑中已移除对已删 `system_health` 的引用）。
